UPFRAME VIDEO EVALUATION STRATEGY
Production Evaluation Plan for 25 FPS -> 50 FPS Football Broadcast Video
Version 1.0

1. PURPOSE

This document defines how to evaluate an AI video frame-interpolation
(upframing) system that converts approximately 25 FPS football/soccer
broadcast video into 50 FPS video.

The goal is not simply to verify that the output contains 50 FPS. The goal
is to determine whether the generated frames create genuinely smoother,
natural-looking motion while preserving players, the ball, pitch geometry,
broadcast graphics, audio synchronization, and overall video quality.

The system uses existing pretrained VFI models such as RIFE, AMT, FILM, or
similar models. No training or fine-tuning is assumed.

Target hardware:
- 3 x NVIDIA L40S, 48 GB VRAM each

Target processing speed:
- approximately 1.0x to 1.3x source duration
- Example: a 60-minute input should ideally finish in 60-78 minutes.


2. THE CORE EVALUATION PRINCIPLE

There is no true 50 FPS ground truth in a normal 25 FPS source.

Example:

25 FPS source:
    A -------- B -------- C

AI 50 FPS:
    A ---- X ---- B ---- Y ---- C
          ^              ^
       generated      generated

We do not know exactly what the real X and Y frames should look like.

Therefore, PSNR, SSIM, VMAF, LPIPS, and similar metrics cannot by themselves
fully evaluate real-world 25->50 FPS interpolation.

Use four evaluation layers:

    Layer 1: Technical / pipeline integrity
    Layer 2: Temporal / VFI quality
    Layer 3: Football-specific visual quality
    Layer 4: Human perceptual quality

Measure performance and reliability separately, but include them in the
production decision.

Build a permanent difficult-segment library covering:

4. REQUIRED BASELINES

Every VFI model must be compared with:

A. Original 25 FPS source

B. Naive 50 FPS frame duplication

Example:
    Original: A -------- B -------- C
    Naive:    A ---- A ---- B ---- B ---- C
    VFI:      A ---- X ---- B ---- Y ---- C

The naive baseline is important because it tells us whether AI
interpolation actually provides useful temporal information beyond simply
displaying each source frame twice.

For model comparisons, keep input, resolution, output FPS, encoder,
bitrate, hardware, and test segments identical.


5. CATEGORY A: TECHNICAL INTEGRITY

Before judging visual quality, verify that the pipeline itself works
correctly.


5.1 FPS

Check:
- source FPS
- output FPS
- actual timestamps
- frame count
- duration

Expected:
- approximately 25 FPS input
- approximately 50 FPS output

Do not assume the source is exactly 25.000 FPS. Inspect its timestamps.


5.2 FRAME COUNT

For constant-rate 25->50 conversion, the output should contain
approximately twice as many temporal samples, accounting for exact timing,
cuts, and container behavior.

Unexpected missing or extra frames indicate a pipeline problem.


5.3 SOURCE-FRAME PRESERVATION

This is one of the most important automated tests.

Conceptually:
    Input:  A -- B -- C -- D
    Output: A -- X -- B -- Y -- C -- Z -- D

The original frames A, B, C, D should remain intact.

Extract the corresponding original samples from the output and compare
them with the input using:
- PSNR
- SSIM
- optionally MS-SSIM
- pixel difference
- frame checksums where appropriate

This detects:
- frame corruption
- color conversion problems
- resizing
- frame ordering errors
- dropped frames
- chunk-boundary errors
- unintended processing of source frames


5.4 AUDIO

Verify:
- audio exists
- duration matches video
- no drift
- no missing audio
- channel layout is preserved where possible

Prefer stream-copying the original audio instead of unnecessarily
re-encoding it.


5.5 TIMESTAMP INTEGRITY

Check:
- PTS continuity
- monotonic timestamps
- no unexpected gaps
- no duplicated timestamps
- A/V synchronization

This matters because real sources may report approximately 25.02 FPS
rather than exactly 25.000 FPS.


5.6 SCENE/CUT INTEGRITY

Verify that no interpolation occurs across hard cuts.

Correct:
    Shot A ---- CUT ---- Shot B

Incorrect:
    Shot A -> artificial hybrid frame -> Shot B


6. CATEGORY B: TEMPORAL / VFI QUALITY

Evaluate whether generated motion is believable.


6.1 TEMPORAL SMOOTHNESS

Watch at normal speed.

The objective is smoother motion without synthetic motion artifacts.

Do not award points simply because the output looks smoother. Smoothness
with ghosting or deformation is not good VFI quality.


6.2 SLOW-MOTION INSPECTION

For important segments, create:
- normal speed
- 2x slow motion
- 4x slow motion
- preferably 8x slow motion for difficult cases

Slow motion exposes:
- warped limbs
- ghost objects
- incorrect ball trajectories
- temporal flicker
- unstable geometry
- interpolation jumps


6.3 INJECTED-FRAME INSPECTION

Extract only newly generated frames.

Example:
    A -- X -- B -- Y -- C

Inspect:
    X
    Y
    ...

This isolates what the model actually generated and is highly useful for
model comparison.


6.4 OPTICAL-FLOW / TEMPORAL CONSISTENCY

Use optical-flow-based analysis where practical.

Conceptually:
    Frame N
       |
       | estimated motion
       v
    predicted next frame
       |
       +---- compare ----> actual next frame

Useful measurements include:
- temporal warping error
- optical-flow consistency
- motion-boundary error
- temporal difference statistics

These are more relevant to VFI than pure pixel similarity because VFI is
fundamentally a motion-estimation problem.


6.5 TEMPORAL FLICKER

Inspect or measure:
- grass texture flicker
- player-edge shimmer
- advertisement flicker
- scoreboard fluctuations
- brightness oscillation
- object appearance/disappearance

A frame can look good individually while looking bad in motion.


7. CATEGORY C: FOOTBALL-SPECIFIC QUALITY

Generic image-quality metrics are not sufficient for football.

Score these explicitly.


7.1 BALL INTEGRITY

Check:
- single ball
- smooth trajectory
- no disappearance
- no teleportation
- no ghost ball
- no elongated/distorted ball

Suggested 1-5 score:
1 = severe failure
2 = frequent/obvious failures
3 = acceptable but noticeable issues
4 = minor issues
5 = essentially clean


7.2 PLAYER INTEGRITY

Inspect:
- legs
- feet
- arms
- hands
- heads
- jerseys
- silhouettes

Look for:
- extra limbs
- missing limbs
- warped bodies
- duplicated players
- melted players
- unnatural body shapes


7.3 PLAYER-PLAYER OCCLUSION

Inspect moments where players cross each other.

Look for:
- ghosting
- transparency
- merged bodies
- duplicated limbs
- disappearing players
- incorrect foreground/background ordering


7.4 PITCH GEOMETRY

Inspect:
- touchlines
- penalty-box lines
- goal-area lines
- center circle
- halfway line

Look for:
- bending
- wobbling
- double lines
- broken lines
- shimmering


7.5 GOAL AND NET

Inspect:
- goalposts
- crossbar
- net

Thin structures often expose incorrect motion estimation.


7.6 CAMERA MOTION

Test:
- slow pans
- fast pans
- tracking shots
- zooms
- camera following the ball

Camera movement should appear continuous rather than producing strange
intermediate frames.


7.7 BROADCAST GRAPHICS

Inspect:
- scoreboard
- channel logo
- TV watermark
- text
- LED advertisements

Look for:
- stretching
- wobbling
- ghosting
- flickering
- shifted logos
- unreadable text


8. CATEGORY D: OBJECTIVE IMAGE / VIDEO METRICS


8.1 PSNR

PSNR measures pixel-level similarity.

Use it mainly for:
- source-frame preservation
- encoding comparison
- controlled experiments with real ground truth

Do not use PSNR alone to judge generated intermediate frames when no
ground-truth intermediate frame exists.


8.2 SSIM

SSIM measures structural similarity.

Use it for:
- source-frame preservation
- encoding tests
- ground-truth VFI experiments

It should not be the primary VFI-quality metric for real 25->50 footage
without ground truth.


8.3 MS-SSIM

Multi-scale SSIM evaluates structure at multiple spatial scales.

Use it as a supporting metric, not a primary production decision metric.


8.4 LPIPS

LPIPS is a learned perceptual similarity metric and can correlate better
with human visual similarity than pure pixel metrics.

Use it as a supporting perceptual metric, especially when genuine
high-FPS ground truth is available.


8.5 VMAF

VMAF is a perceptual video-quality metric.

Useful for:
- encoding comparisons
- compression analysis
- checking whether processing/encoding degrades video quality
- controlled tests with aligned reference and test videos

Do not blindly compare a 50 FPS VFI video with a 25 FPS source. The 25 FPS
reference does not contain the generated frames.

Creating a 50 FPS reference by duplicating frames can unfairly penalize
VFI because the generated frames are intentionally different.


9. GROUND-TRUTH BENCHMARK

If possible, obtain genuine high-frame-rate football footage.

Example true source:
    F0 F1 F2 F3 F4 F5 F6 F7 F8 ...

Create artificial 25 FPS input:
    F0 -------- F4 -------- F8

Run VFI:
    F0 ---- predicted F2 ---- F4 ---- predicted F6 ---- F8

Now compare:
    predicted F2 vs actual F2
    predicted F6 vs actual F6

This is a proper VFI benchmark because the real missing frames are known.

With genuine ground truth, PSNR, SSIM, MS-SSIM, LPIPS, VMAF, optical-flow
metrics, and other interpolation-specific metrics become much more
meaningful.


10. HUMAN SUBJECTIVE EVALUATION

Human evaluation is critical because VFI is a perceptual problem.

Use controlled A/B/C comparisons.

Example:
    A = original 25 FPS
    B = naive 50 FPS
    C = AI 50 FPS

For model comparison:
    A = RIFE
    B = AMT
    C = FILM

Keep:
- resolution identical
- encoding identical
- audio identical
- playback conditions identical
- segment duration identical


10.1 OVERALL QUALITY MOS

Ask:
"How natural and visually pleasing is this video?"

Rating:
    1 = Very poor
    2 = Poor
    3 = Fair
    4 = Good
    5 = Excellent


10.2 INTERPOLATION ARTIFACT SCORE

Ask:
"How noticeable are interpolation artifacts?"

Rating:
    1 = Severe artifacts
    2 = Obvious artifacts
    3 = Noticeable artifacts
    4 = Minor artifacts
    5 = Essentially artifact-free


10.3 MOTION NATURALNESS

Ask:
"How natural and fluid does the motion appear?"

Rating:
    1 = Very unnatural
    2 = Poor
    3 = Acceptable
    4 = Good
    5 = Excellent


10.4 PAIRWISE PREFERENCE

For model selection, pairwise comparison can be more reliable than
absolute scores.

Example:
    "Which version would you prefer for a football broadcast?"
    RIFE vs AMT

Record the percentage of viewers preferring each model.


11. MOS / V-MOS

MOS means Mean Opinion Score.

Example:
    Viewer 1 = 4
    Viewer 2 = 5
    Viewer 3 = 4
    Viewer 4 = 3
    Viewer 5 = 5

    MOS = 4.2

For this project, record at least:
- overall visual quality MOS
- interpolation artifact MOS
- motion naturalness MOS

Generic MOS should be supplemented by football-specific ratings.


12. RECOMMENDED FOOTBALL QUALITY SCORE

Create standardized 1-5 scores for:
- ball integrity
- player integrity
- occlusion handling
- camera motion
- pitch geometry
- goal/net integrity
- broadcast graphics
- temporal stability

Suggested starting weights:

    Player integrity       15%
    Ball integrity         15%
    Temporal stability     15%
    Occlusion handling     10%
    Camera motion          10%
    Pitch geometry          5%
    Broadcast graphics     10%
    Goal/net/thin objects   5%
    Human overall MOS      15%

These weights can be calibrated after collecting real results.

The important principle is that football-specific failures should carry
more weight than tiny pixel-level differences.


13. PRODUCTION PERFORMANCE EVALUATION

Measure:
- total processing time
- interpolations/sec
- frames/sec
- GPU utilization
- GPU memory usage
- CPU utilization
- decoding speed
- encoding speed
- chunk processing time
- load balance between GPUs
- failures/retries

Calculate:

    realtime factor = processing time / source duration

Example:
    90-minute video processed in 99 minutes
    realtime factor = 99 / 90 = 1.10x

Target:
    1.0x <= realtime factor <= 1.3x


14. MODEL COMPARISON

Run every candidate through exactly the same benchmark.

Example:
    Test footage
         |
         +--> RIFE -> 50 FPS
         |
         +--> AMT  -> 50 FPS
         |
         +--> FILM -> 50 FPS

Keep constant:
- input video
- resolution
- output FPS
- encoder
- bitrate
- GPU hardware
- number of GPUs
- chunking configuration
- test segments

Record:

    Metric                    RIFE    AMT    FILM
    ------------------------------------------------
    Source preservation        ...
    PSNR*                      ...
    SSIM*                      ...
    LPIPS*                     ...
    VMAF*                      ...
    Temporal error             ...
    Ball score                 ...
    Player score               ...
    Occlusion score            ...
    Pitch score                ...
    Graphics score             ...
    MOS                        ...
    Artifact score             ...
    Processing speed           ...
    VRAM                       ...
    Reliability                ...

* Primarily meaningful with genuine ground truth or controlled
  source-frame/encoding tests.


15. DO NOT SELECT THE MODEL BY ONE METRIC

Do not choose a model simply because:
- VMAF is highest
- PSNR is highest
- FPS is highest

The production model should provide the best balance of:
- visual quality
- temporal stability
- football correctness
- processing speed
- operational reliability


16. RECOMMENDED DECISION PROCESS

STEP 1 — Technical integrity
Reject models/pipelines that fail:
- frame ordering
- timestamp integrity
- audio sync
- scene-cut handling
- source-frame preservation

STEP 2 — Performance
Measure production speed.
Target approximately 1.0-1.3x realtime.

STEP 3 — Temporal quality
Measure:
- temporal warping error
- optical-flow consistency
- temporal flicker/anomalies

STEP 4 — Football quality
Inspect:
- ball
- players
- occlusions
- pitch lines
- goals/nets
- camera pans
- scoreboard/watermark
- LED boards

STEP 5 — Human evaluation
Collect:
- MOS
- artifact score
- motion naturalness
- pairwise preference

STEP 6 — Final selection
Use all evidence together.


17. DIFFICULT-SEGMENT REGRESSION SUITE

Create short 5-15 second segments tagged by difficulty.

Examples:
    segment_001.mp4  -> fast_camera_pan
    segment_002.mp4  -> player_occlusion
    segment_003.mp4  -> fast_ball
    segment_004.mp4  -> penalty_box
    segment_005.mp4  -> broadcast_graphics

Whenever the VFI model, weights, dependencies, encoder, chunking, or other
important pipeline component changes, rerun the full regression suite.

19. AUTOMATIC BAD-MOMENT FLAGGING

Eventually the system should identify suspicious timestamps automatically.

Example:

    00:13:42.520
    Possible ball artifact

    00:27:18.440
    Possible player/occlusion artifact

    00:51:06.120
    Possible pitch-line distortion

The evaluator should be able to jump directly to these timestamps.

This dramatically reduces human review time.


20. INITIAL QC THRESHOLDS

Start with conservative technical thresholds and calibrate visual thresholds
using actual football footage.

Technical examples:
- zero dropped frames
- zero decode errors
- no unexpected timestamp discontinuities
- audio/video duration within a small defined tolerance
- high source-frame preservation

Temporal examples:
- flag unusually large temporal residuals
- flag abnormal frame-to-frame brightness changes
- flag excessive optical-flow inconsistency

Scene examples:
- flag interpolation across detected hard cuts

Performance:
- target realtime factor <= 1.3x
- monitor GPU balance and memory

Do not invent universal VFI artifact thresholds before collecting baseline
data. Establish them empirically from actual outputs.


21. FINAL SCORECARD

For each model, report two separate high-level scores.

QUALITY SCORE:
- overall visual quality
- temporal consistency
- player integrity
- ball integrity
- occlusion handling
- pitch geometry
- graphics stability
- human MOS

PERFORMANCE SCORE:
- realtime factor
- throughput
- GPU utilization
- VRAM
- reliability

Example:

    MODEL: AMT

    Quality Score:       8.8 / 10
    Performance Score:   8.1 / 10
    Realtime Factor:     1.21x
    Artifact Rate:       low
    Human MOS:           4.4 / 5

This is more informative than reporting only a metric such as VMAF = 92.

23. RECOMMENDED V1 IMPLEMENTATION

Start with:

1. Input/output technical validation
2. Original-frame preservation test
3. PSNR + SSIM for source-frame integrity
4. Frame count / FPS / PTS validation
5. A/V sync validation
6. Hard-cut validation
7. Injected-frame extraction
8. Slow-motion clip generation
9. Temporal anomaly / optical-flow analysis
10. Difficult football segment library
11. RIFE vs AMT vs FILM benchmark
12. Human MOS / artifact scoring
13. Processing-time and GPU-performance report

Later add:
- more sophisticated temporal metrics
- automatic ball/player analysis
- automatic artifact classification
- automatic suspicious-frame ranking
- HTML visual dashboards
- larger high-FPS ground-truth datasets


24. FINAL DEFINITION

A good upframed football video is NOT simply a video that:
- has 50 FPS
- has a high VMAF
- has a high PSNR

A good upframed football video:
- creates genuinely smoother motion
- preserves the original frames
- produces believable intermediate motion
- keeps players and the ball intact
- handles occlusions correctly
- preserves pitch geometry
- keeps broadcast graphics stable
- avoids temporal flicker and hallucinated objects
- handles cuts correctly
- stays synchronized with audio
- can be generated within the required production time

The evaluation system should therefore answer four questions:

1. DID THE PIPELINE WORK CORRECTLY?
2. DID THE MODEL CREATE BELIEVABLE MOTION?
3. DOES THE RESULT LOOK GOOD FOR FOOTBALL BROADCAST VIDEO?
4. IS THE SYSTEM FAST AND RELIABLE ENOUGH FOR PRODUCTION?

Only when all four answers are satisfactory should a model be considered
production-ready.
